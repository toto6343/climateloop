|---|---|

| 공모 주제 | AI 활용 체험·참여형 기상·기후 교육 콘텐츠 개발 |

## 1. 개요

> ⚠️ **이 문서는 기획 단계에서 작성한 PRD입니다.** 3~14장은 초기 설계 의도를 담고 있으며,
> 일부는 계획 상태로 남아 있습니다. **현재 실제로 동작하는 범위는 아래 [1.4 구현 현황](#14-구현-현황)을 기준으로 판단해 주세요.**

### 1.1 한 줄 요약
지역을 선택하면 지역별 기상 조건(4종 시나리오)에 따라 태양광·풍력·수력·화력의 상대 적합도를 비교해주고, 사용자가 직접 에너지 믹스를 조정하면 그 선택이 탄소배출과 전력망 안정성에 미치는 영향을 **즉시 재계산해** 보여주는 웹 시뮬레이터.

> "즉시 재계산"은 조작할 때마다 서버가 값을 다시 계산해 화면에 반영한다는 뜻입니다.
> 기상청 실시간 관측·예보 API를 호출한다는 의미가 아닙니다. ([1.4 구현 현황](#14-구현-현황) 참고)

### 1.2 문제 정의
- 일반 시민은 "에너지 정책"과 "기후변화"를 별개의 이야기로 받아들이는 경우가 많고, 둘 사이의 인과관계를 체감할 기회가 적다.
- 기상 데이터(일사량, 풍속 등)와 에너지 발전 효율의 관계, 그리고 에너지 믹스와 탄소배출·기후변화의 관계는 각각 따로 보도되지만, 하나의 순환 구조로 연결해서 보여주는 콘텐츠는 드물다.
- 공공데이터(기상청, KIER, KPX, GIR 등)가 충분히 개방되어 있음에도, 일반인이 접근 가능한 형태로 가공·시각화된 사례는 적다.

### 1.3 목표
- 기상·기후 데이터와 에너지 데이터를 결합해, 사용자가 "조작 → 결과 확인 → 이해"하는 체험형 학습 경로를 제공한다.
- 결정론적 계산 엔진(정규화 지수 기반 추정)과 LLM 설명 에이전트를 결합해, 단순 통계 나열이 아닌 상황별 해설을 제공한다.
  - **현재 구현에서 "AI"에 해당하는 것은 LLM(Gemini) 설명 에이전트뿐입니다.** 점수·적합도·추천은 모두 규칙 기반 계산입니다. 물리 기반 추정 모델은 향후 확장 계획입니다([9장](#9-핵심-계산-로직-개요) 참고).
- 해커톤 본대회(8/21~22) 기준으로 2일 내 구현 가능한 MVP 범위를 명확히 정의한다.

### 1.4 구현 현황

**기준일: 2026-08-03.** 이 표가 실제 동작 범위에 대한 단일 기준입니다.

#### ✅ 구현 완료

| 기능 | 설명 |

현재 사용하는 배출계수와 지역별 효율계수는 **공식 통계가 아니라 상대 비교용 시뮬레이션 값**입니다. 근거와 교체 방법은 [9.3.1](#931-적용-배출계수와-그-한계-중요)에 정리했습니다.

## 3. 타겟 사용자

- **일반 시민·학생**: 자신의 지역이 어떤 에너지에 유리한지, 에너지 선택이 기후에 어떤 영향을 주는지 체험하며 학습
- **심사위원**: 기상 조건과 에너지의 인과 구조를 얼마나 명확히 전달하는지, AI 활용도, 발표 데모의 직관성을 평가. *(수치의 절대 정확도는 현 단계에서 주장하지 않으며, 사용된 계수의 성격은 [1.4](#14-구현-현황)·[9.3.1](#931-적용-배출계수와-그-한계-중요)에 명시)*

## 4. 핵심 컨셉

> "날씨가 에너지를 결정하고, 에너지 선택이 다시 기후를 바꾼다"

단방향(에너지 → 기후 영향)이 아니라, 기상 → 에너지 → 기후 → (장기적으로) 다시 기상에 영향을 주는 순환(loop) 구조로 설계한다. 4개 모듈로 구성한다.

| 모듈 | 이름 | 핵심 질문 | 데이터 방향 |
|---|---|---|---|
| Module 1 | 지역 에너지 적합도 | 내 지역은 어떤 에너지가 유리할까? | 기상 → 에너지 |
| Module 2 | 에너지 믹스 임팩트 | 내가 고른 에너지 조합이 기후에 미치는 영향은? | 에너지 → 기후 |
| Module 3 | AI 설명 어시스턴트 | 왜 이런 결과가 나왔을까? | 결과 → 설명 |
| Module 4 (확장) | 미래 기후 시나리오 | 2050년엔 이 지역 에너지 효율이 어떻게 바뀔까? | 기후변화 → 에너지 (장기) |

### 7.1 즉시 사용 가능한 글로벌 오픈데이터셋 (가입·승인 불필요)

한국 공공데이터 API는 대부분 가입 후 활용신청 → 승인 절차가 필요하다. 승인 지연에 대한 안전장치, 또는 "한국 vs 해외" 비교 기능이 필요하다면 아래 데이터셋은 가입 없이 즉시 다운로드/호출이 가능하다.

| 데이터셋 | 제공기관 | 형식/해상도 | 활용 방식 |
|---|---|---|---|
| NASA POWER | NASA | 전 세계, 일/시간 단위, API 또는 CSV | 일사량·기상 데이터 즉시 호출, 승인 전 임시 대체용 |
| Global Solar Atlas | World Bank / DTU | 전 세계 250m 격자, GeoTIFF | 태양광 잠재량 글로벌 비교, KIER 자원지도와 교차검증 |

## 9. 핵심 계산 로직 개요

> 📌 **구현 여부를 절에 표시했습니다.** 9.1·9.2의 물리 공식은 **현재 구현되어 있지 않습니다**(향후 확장 계획).
> 실제로 동작하는 것은 9.0의 정규화 지수 곱셈과 9.3의 배출량 가중평균입니다.

### 9.0 현재 구현된 추정 방식 ✅

물리 모델 대신, 지역·기상·믹스의 **상대 관계를 표현하는 무차원 지수의 곱셈**으로 계산한다.

```
태양광 적합도 = 재생에너지 비중(%) × 지역 solar 계수 × 기상 solar 배수   (100 상한)
풍력 적합도   = 재생에너지 비중(%) × 지역 wind 계수  × 기상 wind 배수    (100 상한)
수력 적합도   = 45 × 지역 hydro 계수                 (믹스·기상과 무관한 고정 지수)
화력 적합도   = 화력 비중(%) × 지역 thermal 계수
공급          = (태양광 적합도 + 풍력 적합도) / 2 + 원자력 비중 + 화력 비중
수요          = 100 × 기상 demand 배수
```

가정과 한계를 명시한다.

- 위 값은 **무차원 상대 지수**이며, kW·kWh 등의 물리량이 아니다. 절대 발전량을 주장하지 않는다.
- 적합도 4종 중 **태양광·풍력·화력은 현재 에너지 믹스에 연동**되고, **수력만 고정**이다. 따라서 이 차트는 "지역 고유의 잠재량"이 아니라 "현재 선택한 믹스가 이 지역·이 기상에서 얼마나 실현되는가"를 나타낸다.
- 공급 식에서 재생에너지를 2로 나눈 것은 간헐성을 거칠게 반영한 **설계 선택**이며, 특정 문헌에서 유도한 계수가 아니다.
- 수력은 적합도 바에는 있으나 **공급 합계에는 포함되지 않는다.**
- 지역 계수(17시·도 × 4개 발전원 = 68개 값)의 성격은 [1.4](#14-구현-현황) 및 `backend/scripts/seed_db.py` 주석 참고.

### 9.1 태양광 발전량 추정 ❌ 미구현 (향후 확장 계획)
- 입력: 지역 일사량(kWh/m²/day), 패널 면적, 모듈 효율, 성능비(performance ratio)
- 공식 개념: `발전량 = 일사량 × 패널면적 × 모듈효율 × 성능비`
- 참고: SolarShield 프로젝트의 태양 고도각 계산 로직을 일사량 보정에 재활용 가능
- **전제**: 기상청 관측 일사량 연동(현재 미구현)이 선행되어야 한다.

### 9.2 풍력 발전량 추정 ❌ 미구현 (향후 확장 계획)
- 입력: 평균 풍속, 터빈 스윕면적, 공기밀도, 파워커브(절단풍속 포함)
- 공식 개념: `발전량 = 0.5 × 공기밀도 × 스윕면적 × 풍속³ × 출력계수` (정격용량 상한 적용)
- **전제**: 관측 풍속 또는 풍력기상자원지도 연동(현재 미구현)이 선행되어야 한다.

### 9.3 탄소배출/기후영향 추정 ✅ 구현
- 입력: 에너지 믹스 비율 × 발전원별 배출계수
- 공식: `배출량(gCO2/kWh) = Σ(에너지원 비율(%) × 해당 배출계수) / 100`
- 출력: 추정 배출량(gCO2/kWh), 화력 100% 시나리오 대비 감축률

#### 9.3.1 적용 배출계수와 그 한계 (중요)

> **현재 구현에 사용된 배출계수는 공식 통계 수치가 아니라 시뮬레이션용 예시값입니다.**

| 발전원 | 적용 계수 (gCO2/kWh) |
|---|---|
| 재생에너지 | 12 |
| 원자력 | 12 |
| 화력 | 650 |

- **출처**: 확인되지 않음. 특정 기관이 공표한 값을 인용한 것이 아닙니다.
- **목적**: "화력 비중을 줄이면 배출이 줄어든다"는 인과를 학습자가 조작하며 체감하도록 하는 **상대 비교**에 있습니다. 절대 수치의 정확도를 주장하지 않습니다.
- **표기 원칙**: 화면 각주·툴팁, PDF 리포트, `GET /confidence/levels` 응답에 예시 계수임을 명시했습니다. (`POST /calculate` 응답에는 면책 필드가 없으며 화면 각주로 대체합니다. 표기 위치 전체는 [1.4](#14-구현-현황)의 표 참고.) 사용자가 이 값을 공식 통계로 오인하지 않도록 하는 것이 우선입니다.
- **재생에너지와 원자력이 같은 값(12)인 이유**: 두 전원 모두 발전 단계에서 연료를 태우지 않는 무탄소 전원이라는 점만 반영한 단순화입니다. 전 주기(제조·건설) 관점에서는 두 값이 같지 않으며, 이 시뮬레이터는 그 차이를 표현하지 않습니다.
- **정식 활용 전 필요 조치**: 온실가스종합정보센터(GIR) 또는 EG-TIPS가 공표한 발전원별 배출계수로 교체해야 합니다.
- **교체 방법**: `backend/main.py`의 `EMISSION_FACTORS` 딕셔너리 한 곳만 수정하면 계산·점수·차트·PDF에 일괄 반영됩니다. 적용된 계수는 `GET /confidence/levels`의 `emission_factors` 필드로 확인할 수 있습니다.

같은 원칙이 지역별 발전효율 계수(`backend/scripts/seed_db.py`)에도 적용됩니다. 17개 시·도의 태양광·풍력·수력·화력 계수는 지역 간 **상대 유불리를 표현하기 위한 정규화 지수**이며, 특정 데이터셋에서 그대로 가져온 값이 아닙니다.

### 9.4 AI 설명 에이전트 동작 ✅ 구현 (Q&A는 미구현)
- 계산 결과(수치)를 LangGraph 노드에 전달 → Gemini API가 자연어 해설 생성
- LLM은 **해설만** 담당한다. 점수·적합도·다음 행동 추천은 모두 백엔드의 결정론적 계산 결과이며, LLM이 수치를 만들지 않는다.
- Gemini 호출이 실패·비활성화되면 계산 결과 기반의 결정론적 요약 문구로 대체된다. **화면과 PDF 모두 이 폴백 문구를 "AI 어시스턴트" 영역에 그대로 표시하므로, 표시된 문장이 LLM 생성물인지 폴백인지 구분되지 않는다.** (현재 한계)
- *(미구현: 사용자 자유 질문에 대한 후속 응답 — 1.4 참고)*

## 12. 차별화 포인트 및 기대효과

> 📌 아래는 **현재 구현 기준**의 차별화 포인트입니다. 외부 데이터 연동은 포함되지 않습니다([1.4](#14-구현-현황) 참고).

- 기상 → 에너지 → 기후의 순환 구조를 하나의 인터랙션 흐름으로 연결한 점이 단순 통계 대시보드와의 차별점
- 학습 동기 설계(ARCS Confidence)를 계산 계층에 직접 구현: 목표 대비 위치, 4단계 레벨, 점수 요인 분해, 재현 가능한 다음 행동 추천을 결정론적으로 산출
- 출처가 불확실한 수치를 **화면·PDF·API에 계수와 한계까지 공개**하는 방식으로 다뤘고, 기관명을 임의로 인용하지 않음
- AI 설명 에이전트로 단순 시각화를 넘어 "왜 그런지"까지 답변, 교육적 효과 강화
- **향후 확장 시** 공공데이터(기상청, KIER, KPX, GIR)를 연동하면 같은 인터랙션 구조 위에서 수치 신뢰도를 확보할 수 있다. 계수는 각각 한 곳(`EMISSION_FACTORS`, `seed_db.py` 표)만 교체하면 전 화면에 반영되는 구조로 만들어 두었다.

## 13. 리스크 및 고려사항

- **데이터 신청 지연**: 공공데이터포털 API는 승인까지 최소 1일 소요되므로 접수 초기에 미리 신청
- **트래픽 제한**: KPX 개발계정은 일 100건 제한 → 핵심 데이터는 사전 다운로드 후 로컬 캐싱
- **수치 정확성**: 임의 추정치를 사실처럼 표기하지 않는 것을 원칙으로 삼았다. **현재 배출계수·지역 효율계수는 공식 발표 자료가 아니라 상대 비교용 예시값이며, 그 사실을 화면·PDF·문서에 명시했다**([9.3.1](#931-적용-배출계수와-그-한계-중요) 참고). GIR/EG-TIPS 공표 계수로의 교체는 향후 과제로 남아 있다.
- **데모 안정성**: 해커톤 현장 네트워크 이슈에 대비해 실시간 API 호출보다 사전 캐싱 데이터를 기본값으로 사용
